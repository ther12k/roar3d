# [RB-019] Implement mode choice and contextual permission UX

**Scope:** mvp · **Milestone:** M1 · **Priority:** P0 · **Relative size:** M

**Owner role:** Audio/UI

## Outcome

Request microphone access only after a clear voluntary choice.

## Implementation

1. Build Voice/Touch selection and privacy pre-prompt.
2. Handle asynchronous grant/denial/permanent denial with supported OS APIs.
3. Persist selected input mode and provide settings recovery without prompt loops.

## Acceptance criteria

- [ ] Fresh boot and Touch flow do not prompt for microphone.
- [ ] Denied permission still allows all gameplay.
- [ ] Permission result is not confused with a synchronous return value.

## Required evidence

Fresh-install permission matrix.
