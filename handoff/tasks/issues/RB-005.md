# [RB-005] Prove mic permissions and hardware release lifecycle

**Scope:** mvp · **Milestone:** M0 · **Priority:** P0 · **Relative size:** L

**Owner role:** Audio/Platform

## Outcome

Prove explicit capture can start and stop without playback feedback or a misleading privacy indicator.

## Implementation

1. Implement the smallest built-in mic/capture bus prototype with no autoplay.
2. Test permission grant/denial, capture stop, pause/background, repeated holds, and route changes.
3. Observe OS mic indicator after each transition; document a minimal reproduction if input persists.

## Acceptance criteria

- [ ] No app-level audio recording or upload exists.
- [ ] Capture never routes audible microphone sound to speakers.
- [ ] Hardware release result is documented; failures block voice release rather than being relabeled.
- [ ] A Kotlin evaluation occurs only if supported engine behavior cannot meet the requirement.

## Required evidence

Mic lifecycle matrix, privacy-indicator observations, reproduction project if needed.
